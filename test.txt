I. Basic Functionality (Phase 1 & 2 Check)
Ensure the foundation is solid before testing the new parser.

1. Interactive Loop

Input: Run ./mysh

Expected: You see the prompt mysh> . Typing simple commands (like ls) works and returns to the prompt.

2. Built-in: Change Directory

Input:

Bash
mysh> mkdir test_dir
mysh> cd test_dir
mysh> pwd
Expected: Output shows the path ending in /test_dir.

3. Built-in: Exit

Input: mysh> exit

Expected: The shell terminates immediately.

II. Parser Verification (Phase 3 Check)
Crucial: Since you haven't implemented dup2 yet, the output will NOT redirect to a file. It will print to the screen. The "success" is that the shell doesn't crash or pass the > symbol to the command.

4. Output Redirection (>)

Input: mysh> ls -la > output.txt

Success (Phase 3):

The ls -la command runs and prints file details to your screen.

CRITICAL: It does NOT print an error like ls: cannot access '>': No such file.

Why: This proves your parser successfully removed > and output.txt from the argument list.

Failure: ls complains about the > symbol.

5. Append Redirection (>>)

Input: mysh> echo hello >> log.txt

Success (Phase 3):

Prints hello to the screen.

Does not print >> or log.txt.

6. Input Redirection (<)

Input: mysh> wc -l < existing_file.txt

Success (Phase 3):

wc runs. It might hang (waiting for keyboard input) or print 0.

CRITICAL: It does not say wc: <: No such file or directory.

Note: You may need to press Ctrl+C to stop it if it hangs (since we haven't wired up the input file yet).

7. Background Job (&)

Input: mysh> sleep 5 &

Success (Phase 3):

The shell waits for 5 seconds (because Phase 5 "skip wait" logic isn't implemented yet).

CRITICAL: It does not print sleep: invalid time interval '&'.

Why: This proves the parser stripped the & token correctly.
